> ワークフロー上の位置: 定期作業(開発ループ外)。差異が見つかったら [/fix](../fix/SKILL.md) の仕様変更フローへ

# 実行タイミング

- **毎年7月**: 雇用保険の賃金日額上限は毎年8月1日に改定される(毎年発生が確実)。健康保険の標準報酬月額上限に連動する出産手当金の上限も合わせて確認する
- **毎年4月**: 年度替わりの制度改正(給付率の変更・新給付の創設など。例: 2025年4月の出生後休業支援給付金の新設)
- ニュース等で育児休業・出産関連の制度変更を見かけたとき(随時)

# 実施方法

本Skillの手順はlaw-revision-checkerエージェント(`.claude/agents/law-revision-checker.md`)を起動して行う(Web調査が重く、メインスレッドの文脈を消費しないため。役割分担の背景は[docs/adr/0002](../../../docs/adr/0002-skill-agent-separation.md)を参照)。

- エージェントには確認の目的(7月の上限改定/4月の制度改正/ニュース起点ならその内容)を伝えて起動する
- エージェントの報告(前提値ごとの突き合わせ表)をそのままユーザーに提示し、差異があれば[/fix](../fix/SKILL.md)を案内する

以下の手順はエージェントが従う内容。エージェントを使えない状況ではメインスレッドが直接実行する。

# Step1 現在の前提値を洗い出す

コードとspecの両方から、法令由来の数値・条件を集める。

```bash
# コード側: 定数と適用期間コメント
grep -n "上限\|LIMIT\|% \|給付率" app/ikukyu/lib/calculator.ts
# spec側: ビジネスルールの数値
grep -rn "上限\|%\|日間\|週間" specs/ikukyu/*/requirements.md
```

主な確認対象(2026年7月時点):
- 賃金日額上限(雇用保険): `DAILY_WAGE_LIMIT` — 毎年8月1日改定
- 出産手当金の日額上限(健康保険): `DAILY_HEALTH_LIMIT` — 標準報酬月額の上限等級に連動
- 給付率: 育休前期67%・後期50%・産後パパ育休の上乗せ、前期→後期の切替日数(180日)
- 対象期間: 出産手当金の産前42日/産後56日、産後パパ育休の28日上限・出生後8週間

# Step2 公式資料と突き合わせる

WebSearchで最新の公表値を確認する。**根拠にしてよいのは公式資料のみ**(厚生労働省・ハローワーク・協会けんぽの告示/リーフレット)。まとめサイト・ブログの数値をそのまま使わない。確認した資料のURLと適用期間を必ず控える。

# Step3 差異があれば仕様変更フローへ

- 差異は「仕様そのものの変更」なので、[/fix](../fix/SKILL.md)のStep2(3点セットへの影響洗い出し)→仕様承認PRのフローに乗せる
- specのビジネスルールには改定後の数値と根拠(資料名・URL・適用期間)をセットで書く
- コードの定数コメントには適用期間を残す(例: `// 上限値(2026年8月1日〜2027年7月31日適用)`)。適用開始日より前にマージする場合は、切替日をユーザーと相談してからリリースする
- テストの期待値も同じ変更で更新する(上限境界のテストは新旧両方の値で意味が変わる点に注意)

# 差異がなかった場合

「確認した資料・確認日・変わっていなかったこと」を1行でユーザーに報告して終了する(リポジトリへの記録は不要)。

# 完了時の次ステップ案内

- 改定あり → [/fix](../fix/SKILL.md)(仕様変更を伴うため仕様承認PRから)
- 改定なし → 完了。次回は翌年7月/4月(またはニュース時)
