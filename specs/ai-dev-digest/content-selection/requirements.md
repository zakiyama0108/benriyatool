# 要件定義: 情報源ウォッチリストと採用基準

## 概要
- 機能名: 情報源ウォッチリストと採用基準
- 目的: 「相当ランクの高い、信頼できる発信者」の情報だけを扱いつつ、日によって記事内容が空になることのないよう、日次で取り上げるトピックを定量的に選び出す
- 優先度: 高

## ユーザーストーリー
- 運営者として、無名の発信者や偶然バズっただけのコンテンツではなく、業界で実績のある組織・発信者の情報だけを扱ってほしい
- 運営者として、その日は基準を満たすトピックが少なくても、記事が空にならず一定量のコンテンツが毎日出てほしい
- 運営者として、基準を満たすトピックが慢性的に少ない状態が続く場合は、基準そのものが厳しすぎる可能性に気づけるようにしてほしい

## 機能要件

### 情報源(ウォッチリスト)
- [1] 対象とする情報源は次の13件に限定する(固定リスト運用とし、記載以外の発信者・組織をエージェントが自律的に追加することはしない)

| 区分 | 名称 | チャンネル |
|---|---|---|
| 公式組織 | Anthropic | 公式ブログ・YouTube |
| 公式組織 | OpenAI | 公式ブログ・YouTube |
| 公式組織 | LangChain | 公式ブログ・YouTube |
| 公式組織 | AWS | AI/ML関連の公式ブログ・YouTube |
| 公式組織 | DeepLearning.AI | YouTube・The Batchニュースレター |
| 個人YouTube | Andrej Karpathy | YouTube |
| 個人YouTube | Fireship | YouTube |
| 個人YouTube | Cole Medin | YouTube |
| 個人YouTube | freeCodeCamp | YouTube |
| 個人YouTube | Dave Ebbelaar | YouTube |
| 個人ブログ | Simon Willison | 個人ブログ(simonwillison.net) |
| プラットフォーム | Qiita | プラットフォーム全体(いいね数上位) |
| プラットフォーム | Zenn | プラットフォーム全体(いいね数上位) |

- [2] X(Twitter)は対象に含めない(根拠: 公式APIが有料(Basic tier月額$100〜)で、無料枠では発信者のフォロワー数取得や検索が実質できないため)。X中心の発信者(LangChain CEOのHarrison Chase等)は、LangChain公式の発信でカバーする
- [3] ポッドキャストは今回のスコープに含めない(根拠: 音声のトランスクリプト取得に実装コストがかかるため。将来検討)

### 採用基準(種別ごとの定量判定)
- [4] 公式組織の新着投稿(ブログ記事・YouTube動画)は、原則としてすべて採用候補にする(根拠: 発信量が少なく、内容の信頼性が高いため)
- [5] 個人YouTubeチャンネルの動画は、そのチャンネルの直近動画群の平均再生回数を明確に上回るものだけを採用候補にする(根拠: 登録者数や再生数の絶対値による閾値では、チャンネルごとの規模差を吸収できないため。相対的にそのチャンネル内で特に話題になった動画を拾う)
- [6] Simon Willisonの個人ブログは、新着投稿を原則として採用候補にする
- [7] Qiitaの新着記事は、いいね数30以上のものを採用候補にする
- [8] Zennの新着記事は、公式RSSフィードで新着を発見し、要約のために開く記事の公開ページに表示されているいいね数を読み取って、30以上のものを採用候補にする(根拠: Zennには公式のいいね数取得APIがなく、非公式APIの利用は避ける方針のため。要約のためにどのみち開く公開ページの表示値を使うことで、非公式APIを使わずに済む)

### 1日の掲載件数
- [9] 1日のダイジェストに含めるトピック数は3〜5件とする
- [10] 上記[4]〜[8]の基準を満たす採用候補が3件に満たない日でも、実在する候補(基準未達の候補を含む)が1件以上あれば、その件数のまま掲載する(3件に届かせるために架空の話題を作ることはしない)。基準未達の候補で採用したトピックには、基準を満たしていない旨を分かりやすく示す(具体的な表示方法は設計で詰める)。収集した候補が実在するものも含め1件もない日のみ、その日はスキップする
- [11] [10]による基準未達での掲載が発生した場合、その事実(発生日・情報源・基準からの乖離度合いなど)を記録する。記録した内容は[watchlist-review/requirements.md](../watchlist-review/requirements.md)の月次見直しで参照し、基準未達が慢性的に続く場合は採用基準そのものを見直す(根拠: 基準未達が続くのは基準設定が実態に合っていないサインであるため)

## ビジネスルール・制約

### データ取得方法
- [1] 各情報源の取得は、公式API・公式RSSフィード・公式の埋め込み機能・公開ページの閲覧の範囲にとどめ、非公式API・認証回避・利用規約の想定を超えた高頻度アクセスは行わない(根拠: 各サービスの利用規約遵守。Zennのいいね数取得([9]参照)はこの原則の具体例)

## 依存関係
- 選定されたトピックは[article-detail/requirements.md](../article-detail/requirements.md)で表示される
- 選定候補の翻訳・要約は[content-generation/requirements.md](../content-generation/requirements.md)のルールに従って行われる
- ウォッチリスト・採用基準の変更は[watchlist-review/requirements.md](../watchlist-review/requirements.md)の月次見直しでのみ行う(このspec自身の基準値を日次運用の中で自動的に変更することはしない)
- 収集・選定の実行タイミングは[daily-publish/requirements.md](../daily-publish/requirements.md)に従う

## スコープ外
- プラットフォームを横断した統合スコアによるランキング化(単位の異なる指標を正規化して比較することはしない)
- ウォッチリストへの新規情報源の自動発掘(固定リスト運用)
- ポッドキャストの取得・要約
- X(Twitter)の取得
