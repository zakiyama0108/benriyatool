# 設計: 使い方ガイド

資産推移シミュレーター(`app/life-money-sim/page.tsx`)に、各カードの「？」アイコンによるコンテキストヘルプ、画面上部の使い方バナー、用語集モーダルの3つの表示補助を追加する。3つとも入力値・計算結果には影響しない純粋な表示機能であり、Supabase等の外部通信は発生しない(使い方バナーの開閉状態のみブラウザのlocalStorageに保存する)。

## 処理フロー

### コンテキストヘルプの開閉を制御する処理
- 対象: 収入・個人支出・世帯按分・収支サマリー・前提入力・家族構成・貯蓄/運用切替・賞与イベント・資産推移グラフ/テーブルの9枚のカードに表示する「？」アイコンとポップオーバー(「世帯按分」は画面上「家計支出」というタイトルで表示されているカード(`HouseholdShareInput.tsx`)に対応する。requirements.mdのビジネスルール上の呼び名と画面表示の呼び名が異なる点に注意)
- 手順:
  1. どのカードのポップオーバーが開いているかを、開いているカードのID(なければ`null`)として画面全体で1つだけ保持する
  2. 「？」アイコンをクリック(タップ)したとき、そのカードが既に開いている場合は閉じ(IDを`null`に戻す)、開いていない場合はそのカードのIDに置き換える。画面全体でIDを1つしか保持しないため、他のカードが開いていれば結果的にそちらは自動的に閉じる
  3. ポップオーバーが開いている状態でその外側をクリックした場合も、IDを`null`に戻して閉じる
  4. 各アイコンには、そのカードのIDに対応する説明文言(初版はrequirements.md「コンテキストヘルプの文言」)を表示する
- 関連するビジネスルール: requirements.md#コンテキストヘルプ(？アイコン)-1、requirements.md#コンテキストヘルプ(？アイコン)-2、requirements.md#コンテキストヘルプ(？アイコン)-3、requirements.md#コンテキストヘルプ(？アイコン)-4

### 使い方バナーの開閉状態を初期化・保存する処理
- 対象: 画面上部(タイトル直下)の使い方バナー
- 手順:
  1. 初回描画時は開いた状態を初期値とする(サーバー側で描画される内容とブラウザでの初回描画を一致させ、ハイドレーション時の不整合を避けるため。ブラウザ保存の確認は次の手順で描画後に行う)
  2. 描画後、ブラウザのストレージに保存済みの開閉状態があれば読み込んで反映する。保存されていない場合は開いた状態のままとする
  3. 読み込みに失敗した場合(プライベートブラウジング等でストレージが使えない環境)は、開いた状態のままとし、エラー表示は行わない
  4. 利用者がバナーをクリックして開閉するたびに、その時点の開閉状態をブラウザのストレージに保存する
  5. 保存に失敗した場合も、画面上の開閉自体はそのまま反映し、エラー表示は行わない(次回訪問時に直前の状態へ戻らない可能性は許容する)
- 前回訪問時に閉じた状態で保存していたリピーターは、初回描画(開いた状態)からマウント後の保存値反映(閉じた状態)までの間、一瞬バナーが開いて見えてから閉じる、というちらつきが起こり得る。これは前述1のハイドレーション対策とのトレードオフとして許容する(要件「次回以降の訪問時もその状態を維持する」は最終的な表示状態としては満たされる。一瞬の開閉自体を無くす対応(初期表示のスケルトン化等)はコストに見合わないと判断しスコープ外とする)
- 関連するビジネスルール: requirements.md#使い方バナー-1、requirements.md#使い方バナー-2、requirements.md#使い方バナー-3、requirements.md#使い方バナー-4、requirements.md#使い方バナー-5、requirements.md#保存できない環境でのフォールバック-1

### 用語集モーダルを開閉する処理
- 対象: 資産推移グラフ・テーブルのカード付近に置く「用語集」ボタンとモーダル
- 手順:
  1. 「用語集」ボタンを押すとモーダルを開き、「差引後余剰」「貯蓄のみモード」「資産運用モード」「マイシナリオ」の4用語とその説明文言(初版はrequirements.md「用語集の文言」)を一覧表示する
  2. モーダル内の閉じるボタン、またはモーダル外側(背景)のクリックでモーダルを閉じる
- 関連するビジネスルール: requirements.md#用語集-1、requirements.md#用語集-2、requirements.md#用語集-3、requirements.md#用語集-4

## エラーハンドリング
- ブラウザストレージ(localStorage)の読み書き失敗に関わるのは使い方バナーの開閉状態保存のみ(コンテキストヘルプ・用語集はメモリ上の状態のみで完結し、外部保存を行わないため対象外)。読み書きはtry/catchで例外を捕捉し、開いた状態にフォールバックしてエラー表示は行わない(要件の「保存できない環境でのフォールバック」どおり)。この機能は表示補助であり、失敗によってシミュレーター本体の収支入力・資産推移計算を止めないことを優先する
- コンテキストヘルプ・用語集の開閉状態は`page.tsx`の他の入力状態(収入・支出・前提条件等)とは独立した状態として持つため、この機能側の不具合が計算結果に影響することはない設計とする

## 画面設計
- 表示項目:
  - 対象9カードのタイトル横に「？」アイコン(小さな丸型ボタン)。ModeToggle・EventListInputは現状カードタイトルが無いため、他カードと同じ見た目のタイトル行を新設する(ModeToggleはカード自体の背景・角丸・シャドウも他カードに揃えて新設する。EventListInputは既存のカード装飾はそのままにタイトル行のみ新設する)
  - 「？」押下時: アイコン付近にポップオーバー(説明文言+背景)を表示
  - 画面上部(タイトル直下)に折りたたみ式の使い方バナー。開いた状態では3ステップの操作ガイドが見える。閉じた状態では見出し行のみ
  - 資産推移グラフ・テーブルのカード付近(現状タイトル行が無いため新設するタイトル行)に「用語集」ボタン
  - 「用語集」押下時: 背景オーバーレイ+中央寄せのカードで、4用語の一覧を表示するモーダル
- 操作:
  - 「？」アイコンのクリック/タップで開閉、ポップオーバー外側のクリックで閉じる
  - バナーのクリックで開閉(状態はブラウザに保存され次回訪問に引き継がれる)
  - 「用語集」ボタンでモーダルを開く。閉じるボタン、またはモーダル外側のクリックで閉じる
- PC(2カラム)・スマホ(1カラム)のどちらでも、ポップオーバー・バナー・モーダルが画面幅からはみ出さないようにする(requirements.md#非機能要件・UI/UX要件)

## 状態管理
- 開いているコンテキストヘルプのカードID(`openHelpId: string | null`)は9箇所のカードで共有するため、`page.tsx`がuseStateで一元管理し、各カードへpropsで渡す(同時に1つしか開けない制約はこの一元管理によって成立する)。取りうる値は9カードのID+`null`の計10通りで状態数自体は3以上あるが、遷移ルールはどの値からでも「クリックしたIDに置き換える(既に同じIDなら`null`に戻す)」「外側クリックで`null`に戻す」の2種類のみで、値によって遷移条件が変わる分岐を持たない(一様な遷移)。図にしても2本の一様な矢印の繰り返しにしかならず本文の記述以上の情報を持たないため、状態遷移図は省略する
- 使い方バナーの開閉状態(`isOpen: boolean`)はUsageBanner内で完結するローカル状態とし、localStorageと同期する。他コンポーネントと共有しないため`page.tsx`には持たない
- 用語集モーダルの開閉状態(`isOpen: boolean`)も同様にGlossaryButton内で完結するローカル状態とする

## セキュリティ
- コンテキストヘルプ・バナー・用語集の表示文言はすべて`usageGuideContent.ts`にハードコードした静的な日本語文字列であり、利用者入力やAPIレスポンスをそのまま描画しない(この機能にXSSの入力経路はない)
- localStorageに保存するのは使い方バナーの開閉状態を表す真偽値1つのみで、収入・支出等の入力値や個人情報は一切保存しない
- ポップオーバー・モーダルの外側クリック判定はクリック位置(DOM要素の内外)のみで行い、外部から注入可能な値には依存しない

## ログ
- 使い方バナーの開閉状態の読み込み・保存に失敗した場合のみ、`console.error`でログを出す(保存する値は真偽値のみのため機微情報は含まれない)。既存の`saved-scenario`等と同様、失敗時のみログを残す方針に揃える
- 「？」アイコン・用語集モーダルの開閉はエラーが起こりえない通常のUI操作のため、ログ出力の対象外とする(通常操作を逐一ログに残しても業務的価値がなくノイズになるため)
