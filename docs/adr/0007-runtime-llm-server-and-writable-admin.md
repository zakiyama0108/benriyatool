# 0007. 匿名投稿型コンテンツアプリのためのサーバー機能追加と管理画面の書き込み権限

## ステータス
提案中

## コンテキスト
- 新規アプリ「ボードゲームのルール確認(board-game-rules)」では、誰でも匿名でボードゲームを登録できるようにしたい。投稿はルールブックの写真をアップロードし、LLMが写真から内容を解析してゲーム情報・ルール(簡単版/詳しい版)を生成する体験にする(要件: [specs/board-game-rules/game-registration/requirements.md](../../specs/board-game-rules/game-registration/requirements.md))
- この解析はLLMの画像入力と、不明項目を埋めるためのWeb検索を要し、外部APIキー(Anthropic APIキー等)を使う。このキーはブラウザに埋め込めない秘密情報であり、匿名の誰でもアクセスできる公開サイトから安全に呼び出すには、キーを保持するサーバー側の処理が必須になる
- サイト全体は[ADR-0001](0001-user-input-database.md)により「Next.js静的エクスポート+Cloudflare Workersでの静的配信、サーバー機能を持たない」構成を全アプリ共通の前提としている。既存アプリ(ai-dev-digest)でもLLM処理は行っているが、GitHub Actions上でのオフラインバッチ実行(Claude Code CLIのヘッドレス実行、運営者個人のサブスクリプション認証)で完結させており、サイト自体はランタイムでLLM APIを呼んでいない([specs/ai-dev-digest/architecture.md](../../specs/ai-dev-digest/architecture.md))
- 今回は「投稿者がその場で写真を撮り、結果をすぐプレビューして確定する」というライブなUXが要件であるため、ai-dev-digestと同じオフラインパイプライン方式は使えず、サイト自体がランタイムでLLM呼び出しを行う初めてのケースになる
- あわせて、匿名の誰でも投稿できる公開コンテンツであるため、内容の誤り・不適切な投稿を運営者が事後に修正・削除できる必要がある。しかし既存の管理画面テンプレート([ADR-0006](0006-admin-screen-oidc-rls.md))は「読み取り専用とし、編集・削除の経路を作らない」ことを前提にしており、これは運営者自身が保有するユーザー結果データの閲覧用途(ikukyu/admin、life-money-sim/admin)を想定した設計だった。今回はコンテンツの性質(利用者が投稿する公開データ)が異なり、事後モデレーションのための書き込み権限が必要になる

## 決定
**この1機能に閉じた最小のサーバー関数を追加し、書き込み権限を持つ管理画面を新しい例外パターンとして認める。**

1. **サーバー機能はCloudflare Workersの関数(Pages Functions相当)として、写真解析エンドポイント1つに限定して追加する**。サイトの静的配信自体([next.config.ts](../../next.config.ts)の`output: "export"`)は変更しない。この関数だけがAnthropic APIキー(Wrangler Secrets)を保持し、写真の解析・Web検索による情報補完を行う。他の機能・他のアプリの静的配信には影響しない
2. **[ADR-0001](0001-user-input-database.md)の「サーバー機能を持たない」という前提は、この1エンドポイントに限り例外とする**。ADR-0001自体は変更せず、本ADRを例外として参照する形にする。今後同種の「ライブなLLM生成が要件のアプリ」が増える場合は、都度この例外を踏襲してよいか、前提自体を見直すかをそのとき判断する
3. **board-game-rulesの管理画面は、[ADR-0006](0006-admin-screen-oidc-rls.md)のテンプレート項目3「読み取り専用とし、編集・削除の経路を作らない」の例外とし、ゲーム情報の編集・削除、コメントの削除を認める**(要件: [specs/board-game-rules/admin/requirements.md](../../specs/board-game-rules/admin/requirements.md))。認証方式(Google OIDC)・アクセス制御(RLS)自体はADR-0006のテンプレートをそのまま踏襲し、書き込み権限の範囲だけを拡張する。ADR-0006のテンプレート自体は変更せず、「運営者自身のデータ閲覧」用途には引き続き読み取り専用を適用する。「利用者が投稿する公開コンテンツのモデレーション」用途に限り、本ADRの例外を適用する
4. 匿名投稿によるコスト攻撃(LLM呼び出しの濫用)を防ぐため、投稿フォームにCloudflare Turnstileによるボット判定を組み込み、サーバー関数はTurnstileの検証に成功したリクエストのみを処理する(根拠: ADR-0001が既に「anonからの大量投稿対策としてTurnstile等の導入を検討する」と予告済みの懸念への対応)

## 検討した代替案

| 候補 | 見送り理由 |
| --- | --- |
| ai-dev-digestと同じオフラインパイプライン方式(GitHub Actions+Claude Code CLIヘッドレス実行、PRマージで反映) | 投稿者がその場で写真を撮り即座に結果をプレビューして確定する、というライブな体験の要件を満たせない。投稿の都度PRを人力で作る運用は「誰でも気軽に投稿できる」という狙いとも矛盾する |
| Next.js全体をSSR(サーバーサイドレンダリング)構成に変更する | 影響範囲がサイト全体・全アプリに及び、静的配信の単純さ・ホスティングコストの低さを失う。今回必要なのは1エンドポイントの秘密情報保持だけであり、過剰な変更になる |
| 管理画面を読み取り専用のまま維持し、誤り修正はDB直接操作(SQLエディタ)に頼る | 個人開発の小規模運用でも、公開コンテンツの誤り・不適切投稿への対応が遅くなりすぎる。運営者が自作画面から即座に対応できることが実用上必要 |

## 影響

**良い点**
- 静的配信の単純さを維持したまま、1機能に限定した最小のサーバー機能追加で要件を満たせる
- 管理画面の認証・アクセス制御の基本方針(Google OIDC+RLS)は既存パターンを踏襲でき、書き込み権限の範囲だけを個別に判断すればよい

**懸念点**
- サーバー関数のバグ・設定ミスがAPIキーの露出につながるリスクが新たに生まれる。Wrangler Secretsの管理・関数コードのレビューを丁寧に行う必要がある
- Turnstileを組み込んでも、ログインなしの匿名投稿である以上、悪意ある投稿・スパムを完全には防げない。即時公開+事後モデレーション+通報ボタンという運用([specs/board-game-rules/game-registration/requirements.md](../../specs/board-game-rules/game-registration/requirements.md)、[specs/board-game-rules/report/requirements.md](../../specs/board-game-rules/report/requirements.md))で対応する前提であり、悪用が増えた場合は承認制への変更を再検討する
- 管理画面の書き込み権限という例外が今回1件生まれたことで、将来「読み取り専用テンプレートを守るか、都度例外を認めるか」の判断が積み重なる。同種の要件(匿名投稿型コンテンツアプリ)が増えた場合は、ADR-0006のテンプレート自体の見直しを検討する
