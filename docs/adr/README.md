# ADR (Architecture Decision Record)

複数のアプリ・機能にまたがるインフラ・アーキテクチャ上の意思決定を記録する場所。
`specs/<アプリ名>/<機能名>/` の requirements.md/design.md が「1つの機能の仕様」を記録するのに対し、
ADRは「なぜこの技術・構成を選んだか」という横断的な決定とその理由を記録する。

## 置き場所のルール

- ファイル名: `NNNN-短い決定内容.md`（`NNNN`は4桁の連番、最新の番号+1を使う）
- 特定のアプリに閉じない決定（DB・ホスティング・認証基盤など）はこの`docs/adr/`直下に置く
- 特定のアプリ内だけで完結する技術選定は、そのアプリの`specs/<アプリ名>/<機能名>/design.md`に書けば足りるためADR化は不要

## フォーマット

1つのADRは以下の見出しで構成する。

- **ステータス**: 提案中 / 採用 / 非推奨 / 別ADRで置き換え
- **コンテキスト**: 何を解決したいか、制約は何か
- **決定**: 何を選んだか
- **検討した代替案**: 他に何を検討し、なぜ採用しなかったか
- **影響**: この決定によって得られるものと、新たに生まれる懸念・制約
