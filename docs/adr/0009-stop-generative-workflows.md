# 0009. 生成・配信・失敗通知ワークフローの停止

## ステータス
採用

## コンテキスト
- digest記事の生成ワークフローはClaude Codeのサブスクリプション認証に依存しており、認証を利用できない状態では実行が失敗する。
- 生成ワークフローの失敗を検知してLINEへ通知する仕組みが残ると、失敗が続く間、通知も繰り返される。
- benriyatool.comは静的サイトとして維持し、リポジトリ内の記事JSONと各digestの記事一覧・詳細・ブックマーク機能を引き続き公開する。
- Supabase Freeの一時停止を避けるため週次ヘルスチェックが必要であり、PRのCIとmainマージ時の静的デプロイも引き続き必要である。

## 決定
Claude CodeまたはGeminiに依存するGitHub Actionsの生成・LINE配信・digest失敗通知ワークフローを停止する。

- 5つのdigestの生成ワークフロー10本、LINE配信ワークフロー5本、`digest-failure-notification.yml`をリポジトリから削除する。
- `ci.yml`、`deploy.yml`、`supabase-health-check.yml`は維持する。PR時の検証、mainマージ時のデプロイ、Supabaseへの週次pingを継続する。
- 既存の`content/`記事JSONと記事閲覧・ブックマーク機能は維持し、静的サイトとして配信する。
- ドメインやホスティングの移行は行わない。

## 検討した代替案

| 候補 | 見送り理由 |
| --- | --- |
| OAuthトークンを削除してワークフローを残す | 生成失敗が継続し、失敗通知も発生し続けるため、停止にならない |
| digest失敗通知だけを止め、生成・LINE配信ワークフローを残す | 失敗する自動実行と記事pushに連動する配信処理が不要な状態で残る |
| CI・デプロイ・Supabaseヘルスチェックも停止する | 静的サイトの更新と品質確認ができなくなり、Supabase Freeのプロジェクトが一時停止する可能性もある |
| サイトやドメインも停止・移行する | 既存記事を無料の静的サイトとして継続公開する方針に反する |

## 影響

**良い点**
- 認証切れによる生成ジョブの失敗と、それに伴うLINE失敗通知が発生しなくなる。
- 既存記事の閲覧機能、静的デプロイ、CI、Supabaseの週次ヘルスチェックを維持できる。

**懸念点**
- 記事の自動生成・LINE配信・失敗通知は行われず、追加記事はリポジトリへのコンテンツ追加とデプロイを通じて反映する。
- ワークフロー削除後も、関連する外部サービスの設定や認証情報がコンソールに残る可能性がある。リポジトリ外の設定変更は本ADRの範囲外とする。
